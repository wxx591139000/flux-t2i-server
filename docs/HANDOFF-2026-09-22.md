## 0. 先读这四条（否则你会踩最贵的坑）

| # | 铁律 | 为什么 |
|---|---|---|
| 1 | **「离线测试全绿」≠「线上生效」** —— 改完 Python 服务端代码必须**重启进程** | Python import 时把代码读进内存，之后不再读盘。端到端测试起的是**新进程**，天然测不出。判据：① `/health` 的 `web_uptime_sec` 若远大于代码改动时间 → 进程比代码老 ② 新端点直接打 → **404 且返回纯文本**。两条要同时看。工具：`py -3.11 tools/check_stale.py` |
| 2 | **测试清单不要手写，扫目录** | 手写必然漏，且漏掉的那组**不报错、只是静默不执行** —— 输出上跟"它通过了"完全一样。所以是 `tests/run_all.py` 扫 `tests/test_*.py` 全跑（现 **18 道**） |
| 3 | **本机 `python` = 3.13，很多包没装** —— 用 `py -3.11` | Flask 等依赖只装在 3.11 上 |
| 4 | ★ **「声明」不等于「约束」** | 一个字段写在配置里 ≠ 运行时有人读它。加配置字段时**必须指出它在哪一行被读**；指不出来就是装饰。见 §4 的许可闸事故 |

## 4. ★ 许可闸（2026-09-22 本轮最重要修复，commit `0c31344`）

### 修的缺口：声明 vs 约束

`commercial_ok` 这个字段在 `servers.json` 里存在了一段时间，也有一道门断言
「Qwen 机必须标 False」—— 但那只证明了**声明正确**，证明不了**约束生效**。

```
$ grep -rn commercial_ok manager/*.py
→ 只出现在 _add_qwen_server.py（一次性脚本）
→ 运行时没有任何一处读它
```

**后果**：flux7（Qwen，Qwen Research License **非商用**）一旦开机就在候选池里，
对外访客的任务可能被派上去跑。**这是法律风险，不是质量偏好。**

### 怎么修的

在 `manager/flux_resident_client.py:_pick_from()` 里加闸，位置在**能力过滤之前**：

```python
if not need_model and not DIRECT_BASE:
    allowed = [c for c in cands if c[0].get('commercial_ok') is not False]
    if allowed and len(allowed) != len(cands):
        ...  # 记日志 + cands = allowed
    elif not allowed:
        logger.warning('🔴 许可闸：所有候选机的模型均不允许对外经营')
        return None, (cands[0][1] if cands else None)
```

四处设计要点：

1. **位置在能力过滤之前** —— 许可比能力更硬（能力不满足只是跑不了，许可不满足是不能跑）
2. **判据是 `is not False`**，不是真值判断 —— 缺字段（None）必须**保留**，
   否则老部署（没这字段）所有机器一起消失，比漏判更危险
3. **`need_model` 显式指定 → 绕过** —— 自用不受商用限制，他点名就是他知情
4. **`DIRECT_BASE` 直连模式 → 绕过** ← 这条是**实测回归事故**换来的，见下

### ⚠️ 直连模式豁免：一次真实的回归事故（别"优化"掉）

首版闸只判 `if not need_model:`，结果 `test_manager_edit_offline.py` **6 项变红**，
日志狂刷「🔴 许可闸：所有候选机的模型均不允许对外经营」。

**根因**：直连模式（`FLUX_RESIDENT_BASE` 有值）下 `probe_all()` 返回的候选机是
`fsm.SERVER_DEFAULT` —— 它**只是连接参数载体**（base/token），不代表"这就是
flux1 那台机器"，但它带着注册表**首台 flux1 的 `commercial_ok: false`**。
于是本地部署 / 已开隧道 / 离线测试场景下，唯一那台"机器"被误判成非商用
→ 全部任务返回"无可用机器" → 超时。

**语义边界**：直连是**用户显式指定了后端**，许可合规由他自己负责
（他知道自己连的是哪台）—— 平台不该拿别处的标签拦他。

### 回归门 `tests/test_commercial_gate.py`（13 项）

四组：① 源码有闸（含"闸在能力过滤之前"的顺序断言）
② 行为验证（真跑 `_pick_from`）：排除非商用 / 保留缺字段 / 两个豁免方向都在 / 全非商用返 None
③ 变异测试：拆掉闸 → 门必须变红（实测 7 项红）
④ 声明侧仍正确：`servers.json` 里 Qwen 机仍标 False

**本门自身踩的两个坑（已写进注释，别重走）**：
1. `tokenize.untokenize` **会补空格**（`c[0].get('x')` → `c [0 ].get ('x')`）
   → 字面串 `assertIn` 全部落空 → 门**假红**（而源码其实是对的）
   → 字面串断言一律用**归一化**后的串
2. `self.skipTest` 制造**静默跳过**：6 项行为验证全跳过而输出仍显示 `OK`
   → **被跳过的验证等于没有验证**。修法：真的失败就 `self.fail`；
   加载受测模块时补 `mod.__file__`（模块顶部有 `BASE_DIR = Path(__file__).parent.parent`）

## 5. 模型能力（2026-09-22 定型，一手实测为准）

### ★ 异构能力表 `MODEL_CAPABILITIES`（`server/flux_resident_server.py`）

替代旧单布尔位 `MODEL_EDIT_CAPABLE`。字段：
`{text2img, edit, multi_ref, mask_param, transparent, max_ref_images, native_res, ref_param, cfg_param}`

| pipeline | t2i | edit | 参考图 | CFG 参数名 | 备注 |
|---|---|---|---|---|---|
| `FluxPipeline`(dev) | ✅ | ❌ | — | `guidance_scale` | **无 `image` 参数**，跑不了图生图 |
| `Flux2KleinPipeline` | ✅ | ✅ | **单张** | `guidance_scale` | **不接受 `negative_prompt`**（传了必 TypeError） |
| `QwenImage21Pipeline` | ✅ | ✅ | **最多 10 张 list** | `true_cfg_scale` | 原生 2048；RGBA 透明；**无独立 mask 入参** |

★ `cfg_param` 必须**显式选名**，不能两个参数名都塞进 cand
（会产生误导日志「已丢弃:['true_cfg_scale']」）。

### ★ 三个易错点

1. **`mask` → `mask_param` 改名**：照 Qwen README 写了 `mask=True`，
   实测 `inspect.signature`（23 个参数）**没有 `mask`**。
   Qwen 的局部编辑是**语义级**的（把标注合成进参考图走 `image=`）。
   → **「支持某功能」≠「有对应入参」**；声明与一手事实冲突时以**一手事实为准**。
2. **Qwen 负向提示词陷阱**：官方 docstring「`negative_prompt` ... **Ignored when
   `true_cfg_scale` is not greater than 1**」，而 `true_cfg_scale` 默认 **1.0**
   → 不调大 cfg，写负向提示词等于没写。
3. **采样参数是模型属性，不是全局常量**：klein 4B 是 step-distilled，
   官方**固定 4 步 + guidance 1.0**。旧 `DEFAULT_STEPS=25 / GUIDANCE=3.5` 是
   dev 时代遗留，**从部署第一天起就在静默劣化质量**。现在由 `MODEL_PROFILES`
   按 pipeline 类名分发（klein→(4,8,1.0) / dev→(25,100,3.5)）。
   **加模型就往 MODEL_PROFILES 加一条。别再用「步数越多越好」的直觉。**

### ★ 模型许可（硬约束，别踩）

- **klein 4B = Apache 2.0 可商用** ✅
- **klein 9B / 9B Base / FLUX.2 dev = FLUX NCL 非商用** ❌
- **FLUX.1-dev = FLUX NCL 非商用** ❌（flux1 已标 `commercial_ok: false`）

## 8. 关键不变式（重构时别顺手改掉）

1. **三态语义不能合并**：`active_names()` 的 `None`（读不到 VPS 事实 → 降级全扫）
   / 空集（确实一台没开 → 不许瞎猜成全量）/ 有值（收敛）。见 `HANDOFF-2026-09-21.md §3`。
2. **离线立即剔除，新增需 CONFIRM=2 轮**（防 SSH 抖动）。
3. **`targets.conf` 必须 LF** —— CRLF 会让 name 带 `\r`，静默失效且零报错。
4. **改 `server/` 下常驻文件 → 第一动作是 `deploy_vps.py`**（更新 VPS mirror），
   **不是 scp 到 GPU 机**。看门狗每 60s 用 mirror 覆盖远端，先 scp 会被打回
   （症状：上传后立刻校验 PASS，几十秒后 md5 变回旧值，mtime 却是新的）。
5. **英文提示词直传，一个字符都不改**；只有含中文才走翻译层
   （单点在 `flux_queue.submit()` 的 `has_chinese()`）。
6. **图生图必须用支持编辑的模型**，判据是**上游声明的能力**，不是模型名字。
   三层保障：上游声明 → 站点透传 `supports_edit` → 前端消费布尔值；
   外加**上游 `_generate` 硬闸**（edit + 不支持 → 400）。
   ⚠️ **光"置灰"不够**：`modelId=""`（自动档）会用**当前已加载**的模型，
   若它是 dev 照样失败 → 上传参考图时**主动替用户选好** + 禁用「自动」档。
7. ★ **许可闸不能"简化"**：`not need_model and not DIRECT_BASE` 两个豁免都必须在
   （见 §4 的回归事故）。判据必须是 `is not False`（缺字段保留）。
8. **scp 的选项必须整体排在文件名之前**（getopt 遇第一个非选项参数就停止解析）。
9. **大 payload 永不进 argv**（Windows CreateProcess ~32K 上限）→ 走 ssh stdin。
   ⚠️ `subprocess.run(..., text=True, input=<str>)` 会把 `\n` **转成 `\r\n`**
   → 远端 bash 收到行尾 `\r`。**全程用 bytes**。
10. **`sqlite3.Row` 没有 `.get()`** —— `job_get()` 拿到的先 `dict()` 再碰。

## 10. git 操作（本机有坑，照抄）

```bash
# 远端操作静默挂死的解法：先清空 credential.helper 列表
git -c credential.helper= -c credential.helper=manager push origin main
```

⚠️ **对「工作区外的盘」（如 E:）写 `.git` 会把对象库搞残** → `fatal: bad object HEAD`。
（那是真缺对象，`count-objects -v` 的 `in-pack` 明显偏小，但**工作区通常完好**。）
恢复：**clone 取 pack 拷回**，**别用 `git fetch`**（残缺库报 `unresolved deltas`）。
预防：**别用 `git stash create`** 做快照，改 `git diff HEAD > patch` + tar 工作区。

## 11. 用户偏好（这个项目的协作方式）

- **结论先行**，去掉铺垫与「好问题 / 很乐意帮忙」这类填充词
- **每条结论附证据**：命令 / 文件路径 / 行号 / md5 / 退出码 —— 让用户能自己复跑验证
- **区分「验证通过」与「没能验证」**；不确定就写「我没验证」，**不猜**
- **失败直说**，附报错原文与下一步，不粉饰
- **不可逆 / 对外动作**（git 提交、删除、发布、发消息）动手前先点名并确认
- **反感人肉一致性负担**（「改一处要同步三处」），愿意为消除它做重构
- **数据诚信是红线**：不接受伪造、补造或估算数据冒充真实观测
- **留痕意识强**：改动要让下一个接手的人/AI 能直接续上
- **改既有资产前必须先备份**，改完逐文件比对，报告**实际改动范围**
- **对外发出的文件，发出时立刻存「已发出」快照**
- 项目称呼用全名（flux-t2i-server / image-gen-site），**不用 A链/B链 简称**
  （本文为便于新手理解保留了 A链/B链 的括注，正式沟通请用全名）
