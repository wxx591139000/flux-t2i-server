## 3. 请求 E：active 收敛（2026-09-21 完成，本会话最重要的架构改动）

### 为什么要做

用户多台 GPU 机，**同一时刻只开一台**，每次手动去 AutoDL 控制台开机。
改之前 `enabled: true` 的语义是「永远探活这台」→ 多数条目 `true` 却离线 →
**每轮选机都要为每台关机机白等一次 SSH 超时**（当天延迟事故主因之一）。

### 现在怎么工作

```
VPS 看门狗每60s逐台 SSH 探活
    │
    ├─ 在线 → 迟滞计数 +1，够 CONFIRM=2 轮 → 进 active
    └─ 离线 → 立即 rm 计数文件（下一轮就从 active 剔除）
    │
    ▼ 原子写（tmp + mv）
/opt/flux-watchdog/active.json
    │
    ▼ manager 每轮 ssh cat 一次（TTL 20s 缓存）
filter_active()  →  候选集只留开机的
    │
    ▼
probe_all()  →  只探开机的那台（关机机零 SSH 开销）
```

### ★ 三态语义（最关键，重构时别合并）

`manager/flux_server_manager.py:active_names()` 返回三种值：

| 返回值 | 含义 | 调用方该做什么 |
|---|---|---|
| `None` | **读不到 VPS 事实**（VPS 挂了/网络不通） | **降级**：原样返回全量候选，全扫。可用性优先 |
| `set()` 空集 | 拿到了事实，**确实一台都没开** | 返回 `[]`，**不许瞎猜成全量** |
| `{'flux6'}` | 正常收敛 | 只探这几台 |

把 `None` 和空集合并成「没信息」→ 都退回全量，是最省事也最错的写法。
`tests/test_active_server.py` 第 8 组就是专门钉这个的变异测试。

### ★ CRLF 陷阱（真机部署后立即踩到，已三处加固）

**症状**：active.json 里 `"flux1\r"` → manager 用 `'flux1'` 匹配**永远不中**
→ 候选集为空 → 「机器明明开着却不出图」+ **全程零报错**（最难查的那种）。

**根因**：`targets.conf` 由 Windows 侧 `gen_targets.py` 写出，默认 CRLF；
远端 bash 的 `read` 把 `\r` 留在**最后一个字段**（= 第 7 段 name）。

**三处加固**（任一处单独失守都能拦住）：
1. 生成端：`gen_targets.py` / `deploy_vps.py` 用 `write_bytes()` 而非 `write_text()`，强制 LF
2. 看门狗：`flux_watchdog.sh` 里 `line=${line%$'\r'}`
3. manager：`active_names()` 里 `str(n).strip()` 归一

### 用户视角

站点 `/create` → 展开「高级选项（模型 / 质量 / 固定种子 / 负向提示词）」→

  - **图生图模式下非 klein 系列自动置灰**，标「不支持图生图」

### ★ 采样参数是模型属性，不是全局常量

旧代码 `DEFAULT_STEPS=25` / `DEFAULT_GUIDANCE=3.5` 是 FLUX.1-dev 时代遗留，
**从部署第一天起就在静默劣化质量**（guidance 错 3.5 倍 + 步数空转）。

现在由 `server/flux_resident_server.py:MODEL_PROFILES` 按 pipeline 类名分发
（klein→(4,8,1.0) / dev→(25,100,3.5)）。**加模型就往 MODEL_PROFILES 加一条。**

### ★ 模型许可硬约束（别踩）

**klein 4B = Apache 2.0 可商用**；**klein 9B / 9B Base / FLUX.2 dev = FLUX NCL 非商用**。
做对外经营的电商服务，**本地模型只有 4B 系列能合法用**。
**不要在 9B/dev 上做质量对比，许可就排除了**。详见 `docs/模型选型评估.md`。

## 7. 关键不变式（重构时别顺手改掉）

1. **三态语义不能合并**（见 §3）—— 这是整条链最容易写错的一处。
2. **离线立即剔除（用户明确要求），新增需 CONFIRM=2 轮**（防 SSH 抖动）。
3. **`targets.conf` 必须 LF** —— CRLF 会让 name 带 `\r`，静默失效且零报错。
4. **改 `server/` 下常驻文件 → 第一动作是 `deploy_vps.py`**（更新 VPS mirror），
   **不是 scp 到 GPU 机**。看门狗每 60s 用 mirror 覆盖远端，先 scp 会被打回
   （症状：上传后立刻校验 PASS，几十秒后 md5 变回旧值，mtime 却是新的）。
5. **英文提示词直传，一个字符都不改**；只有含中文才走翻译层
   （单点在 `flux_queue.submit()` 的 `has_chinese()` 判断）。英文直传是必须的：
   保用户意图 / 翻译有损 / 直传才可复现。
5b. **★ 图生图必须用支持编辑的模型（klein）**，且判据是**上游声明的能力**，
   不是模型名字（2026-09-21 定案）：
   - 图生图要求 pipeline 的 `__call__` 接受 `image`；`FluxPipeline`(dev) 没有
     这个参数 → 跑了必失败。`Flux2KleinPipeline` 可以。
   - 能力表唯一来源：`server/flux_resident_server.py:MODEL_EDIT_CAPABLE`
     （按 pipeline 类名，未识别 → **False** 保守方向）。
   - **不要用 `id` 里有没有 "klein" 去判断** —— 那是拿命名当能力，将来加一个
     名字不含 klein 却支持编辑的模型就误判，且逻辑会散落在两个仓库。
   - 三层保障缺一不可：上游声明 → 站点透传 `supports_edit` → 前端消费布尔值；
     外加**上游 `_generate` 硬闸**（edit + 不支持 → 400 说「换模型」），
     因为前端约束可被绕过（直调 API / 老页面）。
   - ⚠️ 最容易漏的一点：**光"置灰"不够**。`modelId=""`（自动档）= 不传 model
     → 上游用**当前已加载**的模型，若它是 dev 照样失败。所以上传参考图时要
     **主动替用户选好**支持编辑的模型，并且禁用「自动」档。
6. **scp 的选项必须整体排在文件名之前**（getopt 遇第一个非选项参数就停止解析）。
   上传统一用 `fsm.scp_upload_cmd()`。
7. **大 payload 永不进 argv**（Windows CreateProcess ~32K 上限）→ 走 ssh stdin。
   ⚠️ 且 `subprocess.run(..., text=True, input=<str>)` 会把每个 `\n` **转成 `\r\n`**
   → 远端 bash 收到行尾 `\r`。**全程用 bytes**。
8. **sqlite3.Row 没有 `.get()`** —— `job_get()` 拿到的先 `dict()` 再碰。
