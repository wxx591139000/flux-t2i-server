## 4 项上线动作（按顺序）

### ① 订阅事件 `im.message.receive_v1`

飞书开放平台 → 你的图图应用 → **事件与回调 → 事件订阅**，确认已订阅
`im.message.receive_v1`（接收消息）。**私聊已经在用这个事件**，所以要确认的是
**群消息也会通过它投递**。

> 依据：`manager/feishu_bot.py` 的 WS 长连接只处理 `im.message.receive_v1`。

### ② 授群消息权限

飞书开放平台 → **权限管理**，申请并发布：

| 权限 | 作用 |
|---|---|
| `im:message.group_at_msg:readonly` | **只收"@机器人"的群消息** —— 正好与代码的 @ 门对齐（推荐） |
| `im:message` | 若要收群内**全部**消息（**不建议**：代码里"未 @ 即忽略"，收了也是白收，且更容易触发审核） |

⚠️ 权限变更后**需要重新发布版本**，且可能**要重新拉机器人进群**（或等应用权限生效）。

### ③ 把图图拉进目标群

在飞书里把图图机器人拉进要服务的群。**每个群都要拉**。

### ④ 登记群 `chat_id` 到 `manager/.env`

**怎么拿群 `chat_id`（不用翻飞书后台）**：
1. 把图图拉进群（③ 已完成）→ 在群里随便 @ 图图 发一句话
2. 看 `manager/` 的 9620 日志，会有一行：
   ```
   🤖 群 oc_xxxxxxxxxxxxxxxx 不在白名单（FEISHU_ALLOWED_CHATS），忽略
   ```
   那串 `oc_...` 就是群 `chat_id`

然后在 `manager/.env` 加：

```ini
# 多个群用逗号或分号分隔
FEISHU_ALLOWED_CHATS=oc_xxxxxxxxxxxxxxxx

# 图图自己的 open_id（判断群里 @ 的是不是它本人）
# 不配也能跑，但 @ 判定退化为"任意 @ 即响应"（会误响应 @别人 的消息）
FEISHU_BOT_OPEN_ID=ou_xxxxxxxxxxxxxxxx
```

**改完 `.env` 必须重启 9620 才生效**（配置是建实例时读一次的，不是每条消息读）。

## 上线后怎么验（别只看"没报错"）

| 检查 | 期望 |
|---|---|
| 白名单**内**的群，@图图 发提示词 | 有回执（「⏳ 收到！正在解析提示词…」+ 排队确认），结果**回到群里**并只 @ 发起人 |
| 白名单**内**的群，**不 @** 发提示词 | **无任何反应**（代码里"未 @ 即忽略"） |
| 白名单**外**的群，@图图 | **无任何反应**（不回复 = 不暴露机器人存在感，设计如此） |
| 群里 @**别人**（不是图图） | **无任何反应** ← ★ 这条最容易出问题；只有配上 `FEISHU_BOT_OPEN_ID` 才可靠 |
| 私聊 | 不受影响，仍然正常工作（回归门 `t_p2p_unaffected` 已钉） |
| 群与私聊各自设「张数 3」 | **互不影响**（三元组 key；回归门 `t_session_isolation_group_vs_p2p` 已钉） |

**端到端提醒**：验证时**必须有一台 GPU 机在线**，否则任务只会停在 `waiting`，
看不到出图结果（`/health` 的 `backend_hint` 会显示 `server_down`）。
