## §3 关键发现（含证据）

### 3.1 ★ 多图参考的本地安全上限 = 3 张（32G 卡）

| 张数 | 结果 | 请求体 |
|---|---|---|
| 1 | ✅ 68.78s | — |
| 2 | ✅ 77.38s | — |
| 3 | ✅ 87.1s | 348KB |
| 5 | ❌ OOM | 699KB |
| 8 | ❌ OOM | 1.05MB |
| 10 | ❌ OOM | 1.29MB |

OOM 原文（B4b）：`Tried to allocate 578.00 MiB. GPU 0 has a total capacity of 31.47 GiB of which 332.81 MiB is free … 31.14 GiB memory in use`。

**结论**：请求体 1.29MB 远低于 `MAX_EDIT_BYTES=12MB`，**瓶颈是显存**。模型的 `max_ref_images=10` 是**模型能力上限，不是本机安全运行上限**。
→ 平台须引入 `safe_ref_images` 概念（当前 32G 卡 = **3**），超过则前置拦截给用户明确提示，而不是丢给 GPU 爆显存。

### 3.2 ★ 2048 必须开 `expandable_segments`

- 默认 `start_resident.sh` → 2048×2048 在 **14/20 步 OOM**。
- 加 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` 重启 → **211.55s 通过**。
- 结论：建议写进 `start_resident.sh` 环境段（对 1024 无副作用）。

### 3.3 ★ Qwen 默认 CFG=1.0，高 CFG 劣化（同 prompt A/B）

- G1a `true_cfg_scale=1.0` → 干净、自然、细节准。
- G1b `true_cfg_scale=4.0` → **明显过饱和 + 过曝**。
- 背景：flux 系默认 cfg=4.0，Qwen 官方默认 1.0（且负向提示词需 CFG>1 才生效）。
- **风险**：若平台沿用 flux 的 cfg 默认值，B 链用户拿到的 Qwen 出图会系统性偏色。
→ 须按 `model_id` 分派默认参数（cfg：`Qwen-Image-2.1`→1.0，`FLUX.*`→4.0）。

### 3.4 ★ 透明判据：`alpha.min()==0`，不是 `mode=='RGBA'`

实测全部产物：

| 产物 | mode | a_min | a_max | a0 占比 | 真透明？ |
|---|---|---|---|---|---|
| 普通生图（不请求透明） | RGBA | 253 | 255 | 0.00% | ❌ 否 |
| D1（请求 transparent） | RGBA | 0 | 255 | **15.65%** | ✅ 是 |
| D2（抠图） | RGBA | 0 | 255 | **26.66%** | ✅ 是 |

**教训**：Qwen 管线**总是输出 RGBA 容器**，不透明图 alpha 也是 253~255（几乎不透明）。用 `mode=='RGBA'` 当判据 → 6 张不透明图**全部假绿**。
→ 正确判据：`(alpha==0).mean() > 0`（或 `alpha.min()==0`）。
→ **配套坑**：带 alpha 的 PNG **直接渲染是「紫底黑斑」**（透明区 RGB 是噪声），必须先合成白底/棋盘底再判断，否则人眼也会误判。

### 3.5 ★ 柔性编辑区：圈选 / 涂抹 / 掩码三法全通（人眼对比）

- **C1 圈选**（原图 img-016 有三色标记圈）：输出**头发→黑**、**短袖→灰**、**手表移除**、标记线清除 —— 三处编辑全部命中。
- **C2 涂抹**（原图 img-018 右侧白色涂抹区）：输出在该区域**生出潜水员**，位置对应。
- **C4 独立掩码**：模型 `mask_param=false`，直接传 `mask` 被 400 拒绝，文案为「目标模型不支持 mask 入参…请把圈选/涂抹合成进参考图后用 image 传入」—— **与 ob 笔记一致**（原图和独立掩码作为两张图片输入）。

### 3.6 尺寸对齐：任意值吸附到 32 的倍数

- A3 请求 `1000×1000` → 实际 **992×992**（992 = 31×32）。
- A2 请求 `256×256` → 256（本就是 32 倍数）。
→ 平台侧若要精确尺寸，须自行对齐；或文档化「实际输出可能被微调」。

### 3.7 E1 文字修改：部分成功

- 原图 img-009 文字 `BLOOM` → 请求改为 `Qwen-Image`。
- 输出文字位置/字形基本正确，但**拼写为 `Qwon-Image`**。
→ 结论：Qwen 文字编辑能力存在但**非 100% 可靠**，关键文字类交付建议加人工复核环节。

### 3.8 C2 观察：保留参考图比例 + 灰边

- C2 输出为 1024×1024 画布，但**上下有灰色留白带**，内容按原参考图（约 3:2）比例居中。
→ 属边缘编辑「保比例」行为的副作用，属观感问题（P2），不阻断。
