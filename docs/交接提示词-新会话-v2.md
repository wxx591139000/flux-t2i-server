## 附：这份提示词为什么这样写

| 写法 | 理由 |
|---|---|
| 先读文档再动手 | 新会话没有上下文，直接开工会基于猜测。文档里有真实观测数据（端口、md5、命令），能立刻对齐 |
| 要求**复述六件事** | 「是否真读进去」的可验证判据。复述错了 = 理解偏了，比干完活再返工便宜得多 |
| 第 3、4 条点名能力表与解释器 | 这是 2026-09-22 新增的两处**结构性变更**，不点名新会话会按旧心智模型（单布尔位 / 写死 python）去改，必然改错 |
| **第一步就点名「显存是最大未知数」** | 它是唯一没法离线验证的硬门槛（30-35GB vs 32G 卡）。不点名，新会话会以为全绿就等于能用 |
| **第二步点名「一次都没跑过」** | 防止把「环境就绪 + 门全绿」误读成「功能已验证」。这是最容易产生虚假信心的地方 |
| 单列「三个最容易踩的坑」 | 三条都是真踩过的，且**症状都指向错误方向**（覆盖像未落盘 / 中间态像失败 / README 像权威）。放在最显眼处 |
| 附协作方式 | 用户偏好稳定，每次重复一遍比让 AI 猜好 |
