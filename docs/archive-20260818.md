> 归档日期：2026-08-18 · Git 标签：`archive-20260818`

## 本次归档变更摘要

**v1.8 — 一键启动脚本 + 修复 admin 登录 bug**（运维优化 + bugfix）

起因：8/18 早发现 `flux.zhuanlu.xyz` 报 Cloudflare 1033 —— 本地机器重启后 **flux_service 和 cloudflared 隧道全掉**。排查中顺手修了两类问题，并做成一键启动脚本方便重启后手动拉起。

### ① 一键启动脚本（`start_service.ps1` + 4 个 .bat）
- `start_service.ps1` 重构：支持 `-Target all/flux/xhs/tunnel`，可**分别拉起** FLUX 文生图服务(:9620)、小红书发布服务(:8800)、公网隧道
- **修好 cloudflared 启动 bug**：原传 `--config` 参数导致 "tunnel run accepts only one argument" 起不来（1033 根治）；改为 `cd .cloudflared` 目录 + `tunnel run xhs-tunnel`（COORDINATION.md 正确方式）
- ps1 补 UTF-8 BOM（否则含中文的 ps1 被 PowerShell 按 GBK 误读解析报错）
- 新增 `启动-01-FLUX服务.bat` / `启动-02-小红书服务.bat` / `启动-03-仅隧道.bat`；`start_service.bat` 一键全拉
- **规避隐患**：小红书项目旧 `start.bat` 隧道还写 `transcribe-bot`（会抢 VPS 隧道），本脚本统一用正确的 `xhs-tunnel`

### ② 修复 admin 登录 bug
- `/api/admin/users` 返回 `{"accounts":[]}`，前端登录门却检查 `d.users`（永远 undefined）→ 任何 token 都报"Token 错误"
- 改为 `d.accounts!==undefined`（login + 自动刷新 IIFE 两处）

**验证**：脚本幂等（重复跑不重复起进程，各端口 1 监听）；FLUX/小红书/隧道重启后本地+公网全链路 200；admin 用 `flux-admin-2026` 登录恢复正常。
