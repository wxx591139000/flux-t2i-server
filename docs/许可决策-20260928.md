# 许可决策：把 Qwen-Image-2.1 放到 B 链（2026-09-28）

> 版本锚点：**v2.13.0** · 关联改动 `manager/servers.json` + `manager/flux_resident_client.py`
>
> 本文回答一个问题：**为什么 `commercial_ok` 还是 `false`，但 Qwen 已经能被客户用到了？**
> 以及：**这个决定是谁做的、依据是什么、怎么撤回。**

---

## 一、一句话结论

Dancing 于 **2026-09-28** 明确要求把 **Qwen-Image-2.1** 放到 **B 链（`image-gen-site`，面向客户的生图站点）**。
该模型的许可**明确禁止商用**（详见下节），因此这是**业主在知悉风险后的决定**，
实现方式是新增正交字段 `expose_to_customers`，**而不是**修改记录许可事实的 `commercial_ok`。

---

## 二、许可事实（已独立核实，5 条来源）

**结论：`Qwen-Image-2.1` 采用 Qwen Research License —— 仅限研究与评估，商用需另行取得授权，且无自助通道。**

That license covers research and evaluation. **It does not grant commercial use**, and commercial use needs a separate license from Alibaba Qwen. … **And Apache 2.0 is gone.**」并明确对比：同系列 `Qwen-Image 2512` / `Qwen-Image-Edit 2511` **仍是 Apache 2.0**，只有 2.1 换了许可 |

本轮 Dancing 在知悉后仍明确要求放到 B 链 —— 本文即该决定的留痕。

## 三、为什么不去改 `commercial_ok`

两个字段是**正交**的，混成一个会让事实字段撒谎：

| 字段 | 回答的问题 | 性质 | 谁有权改 |
|---|---|---|---|
| `commercial_ok` | **这个模型的许可证允不允许商用？** | 客观**事实** | 谁都不该改（除非上游改了许可） |
| `expose_to_customers` | **业主愿不愿意承担风险、把它放给客户？** | 主观**决定** | 业主（Dancing） |

如果把 `commercial_ok` 直接改成 `true`，下一个接手的人就再也分不清这两种情况：

- 「这个模型本来就能商用」（无风险）
- 「业主决定不管许可」（明知故犯，需要留证）

而这两件事的法律含义完全不同。所以：**事实字段不动，另加一个决定字段。**

## 四、技术落点

### 4.1 注册表（`manager/servers.json`）

```json
"commercial_ok": false,
"license": "Qwen Research License（非商用；商用需单独授权）",
"expose_to_customers": true,
"expose_note": "2026-09-28 Dancing 明确要求……（谁/何时/为什么 + 回滚方式）"
```

### 4.2 判据（`manager/flux_resident_client.py` → `_pick_from`）

```python
allowed = [c for c in cands
           if c[0].get('commercial_ok') is not False      # ① 许可事实允许
           or c[0].get('expose_to_customers') is True]    # ② 业主显式放行
```

两条**或**关系，位置仍在**能力过滤之前**（许可比能力更硬）。两个既有豁免不变：
`need_model`（自用点名）与 `DIRECT_BASE`（直连模式）。

### 4.3 可见性（`_warn_exposed`）

靠 ② 放行的机器**每次进程内首次被选中时**打一条 `WARNING`：

```
⚠️ 许可闸：flux7 的模型**非商用**，但注册表标了 expose_to_customers=true
   → 已按业主决定放行对外使用（依据见注册表 expose_note）
```

按机器名去重（每进程一次）—— 本项目的看门狗专门为日志刷屏做过节流，刷屏会淹掉真正的故障日志。

## 五、影响面（什么会变、什么不会）

| 项 | 变化 |
|---|---|
| B 链下拉框（`/api/models`） | **会**列出 Qwen-Image-2.1（以前这一步被许可闸拦成空清单） |
| 自动选机 | **可能**选中 flux7（不再只挑商用机） |
| 客户显式选 Qwen | 与以前一样可用（`need_model` 豁免，本就不受许可闸限制） |
| B 链前端代码 | **不需要改**（`app/create/page.tsx` 只渲染 `/api/models` 返回的清单，无商业过滤） |
| klein / dev 机器行为 | **不变** |
| 许可事实本身 | **不变**（仍是非商用） |

## 六、回滚（一行）

`manager/servers.json` 里把 flux7 的 `"expose_to_customers": true` **改成 `false` 或删掉该字段**，
然后重启 9620 —— 立刻恢复「仅自用点名可用、对外自动选机不可用」。

回归门 `tests/test_commercial_gate.py` 会守住三件事，回滚后依然全绿：
① 放行分支在源码里；② 放行对自动选机生效；③ 放行**必须**配 `expose_note`（不许悄悄放开）。

## 七、仍未验证 / 待办

1. **⚠️ 端到端没跑过** —— flux7 当前**未开机**，`servers.json` 里的 `host:port` 是**无卡期地址**
   （`connect.weste.seetacloud.com:13889`，实测 `Connection refused`）。
   地址不对 → 看门狗探不到 → flux7 不进 `active.json` 的 `active` 列表 → manager 看不见它
   → **B 链下拉框仍然不会有 Qwen**。本决策只是"把门打开"，机器得先能连上。
2. **Qwen 显存未实测** —— bf16 约 30-35GB vs 32G 卡，登记为 `offload=none`，需带卡实测确认。
3. **商业授权** —— 若要合法对外经营，需向杭州通义实验室申请（无自助通道，据来源 2 约需 2~4 周评估）。
