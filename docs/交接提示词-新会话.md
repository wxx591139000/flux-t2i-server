⚠️ **本轮最容易踩的 4 个坑（都是实际踩过的）**

1. **命令判据既不能放宽，顺序也不能挪**。图图主用法是"发一句话出图"：
   顺序错 → 命令被当提示词**真扣额度出废图**；判据松 → 吞掉
   「取消一切杂乱背景，画面干净」这类正常提示词。
   两条都有回归门（`tests/test_feishu_bot_cancel.py`），**改之前先读门里怎么断言的**。

2. **`status in (...)` 的地方，每加一个状态都要回头审**。
   本轮的真缺陷正是这一类：`waiting` 是 09-20 加的状态，删除逻辑写在 09-21，
   差一天就漏了。★ **内存态集合（`set`/`dict`）最容易漏** ——
   DB 侧全加了墓碑过滤（`deleted_at IS NULL`），内存池那条路径没加。

3. **改 `.py` 后必须重启 9620 才有用**（Python import 后不再读盘）。
   判据两条：① `/health` 的 uptime 远小于代码 mtime ② 新端点返回**纯文本 404**。
   「离线全绿」不等于「线上生效」。

4. **`& script.ps1 @数组` 调子脚本会静默失效** —— `[switch]` 形参一个都绑不上，
   于是 `-NoPause` 失效 → 子脚本里的 `pause` 把编排器**卡死**（且管道 stdin 下看不见）。
   一律用**显式具名参数**。
