⚠️ **本轮最容易踩的 7 个坑（都是实际踩过的）**

1. ★ **永远不要为了让功能生效，去改「记录事实」的字段**（v2.13.0 新增）。
   实例：为了让 Qwen 上 B 链，最省事的是把 `commercial_ok: false` 改成 `true`（一行搞定）——
   **这是错的**，该字段记录的是「许可证允不允许商用」这个**事实**；改了它就再也分不清
   「模型本来就能商用」和「有人为了放行把事实改成了谎话」。
   → 正确做法：**事实字段不动，另加一个正交的决定字段**（+ `expose_note` 留证 + `WARNING` 可见 +
   改回 `false` 即回滚）。可复用判据：**要改的字段记录的是事实（版本号/许可证/实测值/时间戳），
   而你要它表达的是决定或期望 —— 加新字段，不要改事实。**
   门会拦住它：`tests/test_commercial_gate.py::test_registry_still_declares_qwen_noncommercial`。

2. **命令判据既不能放宽，顺序也不能挪**。图图主用法是"发一句话出图"：
   顺序错 → 命令被当提示词**真扣额度出废图**；判据松 → 吞掉
   「取消一切杂乱背景，画面干净」这类正常提示词。
   回归门：`tests/test_feishu_bot_cancel.py` / `tests/test_figu_params.py` / `test_figu_confirm.py`。

3. **判据里出现 `status in (...)` / `phase in (...)`，每加一个状态都要回头审全部条目**。
   这条坑在 v2.10.0 和 v2.11.0 **各踩一次**（`waiting` 一次、`cancelled` 一次）。
   ★ **内存态集合（`set`/`dict`）最易漏**（DB 侧加了过滤、内存池没加）。
   → 修法：**同一语义的判据收敛成常量**（现在是 `FEISHU_TERMINAL_PHASES`），别再各写一份。

4. **改 `.py` 或改 `.env` 或改 `servers.json` 后必须重启 9620 才有用**（都是启动时读一次）。
   判据两条：① `/health` 的 uptime 远小于代码 mtime ② 新端点返回**纯文本 404**。
   「离线全绿」不等于「线上生效」。重启后跑 `py -3.11 tools\check_stale.py` 自证新鲜度。
   ⚠️ 看门狗是例外：它**每轮重读** `targets.conf`，改它不用重启。

5. **`& script.ps1 @数组` 调子脚本会静默失效** —— `[switch]` 形参一个都绑不上，
   于是 `-NoPause` 失效 → 子脚本里的 `pause` 把编排器**卡死**（且管道 stdin 下看不见）。
   一律用**显式具名参数**。

6. **门里写"不产生副作用"的断言，用「前后差值 == 0」，别用「总数 == N」** ——
   总数型断言会把实现里**固有的、无关的**消息一起算进来 → 假红（v2.11.0 踩过一次）。

7. **改一个"默认行为"时，先问「有多少道门依赖这个默认值」** ——
   v2.12.0 把「发提示词直接出图」改成「先确认」，**4 道既有门同时红**（cancel 1 项 / p0 7 项），
   但**没有一处是实现坏了**（它们都用"发一句 → 断言进队列"验证各自的逻辑）。
   正确做法是**改门**（`bot.confirm_enabled = False`），**不是改断言** ——
   改断言会把真缺陷一起改掉。同时必须另留一道门钉住"线上默认值"（`t_default_on`）。
